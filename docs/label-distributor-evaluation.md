# Label and Distributor evaluation

Evaluation of the Label and Distributor derivation (`scraper/labels.py`, `extension/src/core/labels.ts`) over real releases.

## Method and limits

- 94 releases across Warner, Universal, Sony, independents, distribution services, multi-entity and licence lines, old catalogue, classical and non-US storefronts.
- The copyright text is the album record of the Apple iTunes lookup (`itunes.apple.com`, the host the app already uses), fetched sequentially with a pause between requests. The Apple Music page carries the same ℗ line; the live page read of the acceptance and three other links matched it (see the PR report).
- The derivation only reads the ℗ line, so it was run on those lines directly. The iTunes `copyright` field is the album's line, so a few tracks on compilations show a compilation line.
- The correct answer is the reviewer's judgement from the known label structure of each release, plus the ℗ line itself. An independent per-case source (MusicBrainz, Discogs, Wikipedia) was NOT consulted: querying a host the project does not use was not permitted in this session. Treat the 'correct' column as a careful judgement, not as checked against a database.
- 'Expected' values are the after-fix output except where listed as exceptions in the notes (Blackpink, Shaboozey); the 'Before' column is therefore a measure of what the fixes changed, judged against that reviewed result.
- Verdicts: correct (filled values are right and nothing clearly derivable is missing), wrong (a filled value is wrong), missing (should have filled), empty (correctly left empty).
